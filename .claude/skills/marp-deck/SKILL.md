# Marp で発表スライドを作るときに気をつけること

## 書き出しでつまずいた点

- 端末（TTY）でない環境（Claude Code の Bash など）では、marp が標準入力を待って止まる。`< /dev/null` を付けて実行する
- 見た目は、PNG に書き出して一覧にして確かめる（`--images png` で書き出し、ffmpeg の `tile` で並べる）。はみ出しや改行の位置は、原稿を読むだけでは分からない
- 長い日本語のタイトルは、単語の途中で折り返す。`word-break: keep-all` を当て、文字の大きさで 1 行に収める
- front matter の `title:` は、書き出したファイルのタイトルになる。表紙の見出しと揃える
- PDF と PPTX では動画が止まった画像になり、PPTX は各ページが画像で文字を編集できない。動画を流すなら HTML で発表する
- HTML は画像と動画を相対パスで読む。HTML だけを別の場所にコピーすると、図と動画が出ない

## 書き出したファイルの管理

- 発表に使う HTML は git で管理し、clone すればそのまま発表できるようにする。PDF と PPTX は作り直せるので管理しない
- 書き出した HTML は `.prettierignore` に入れる。入れないと Prettier が整形し直す
- 原稿を直したら、書き出し（HTML、スクリプトで作る図やポスター）も作り直してからコミットする。原稿と書き出しがずれたまま残りやすい

## 図をスクリプトで作るとき（puppeteer で HTML を撮る）

- GPU を使うと撮るたびに画素が少し揺れ、毎回バイナリの差分が出る。`args: ['--disable-gpu']` で起動する
- 固定サイズのページに描くと、文言を増やしてはみ出しても、何も知らせずに切れた画像ができる。撮る前に `scrollHeight > clientHeight` を調べ、はみ出していたら例外で止める
- 寸法は定数にまとめ、CSS と `setViewport` の両方から使う

## 内容で気をつけること

### 用語と文言を揃える

- 同じものの呼び方を 1 つに決め、スライド、図、ポスター、想定問答のすべてで通す。図の中の文言（スクリプトの中）も忘れずに直す
- 同じ内容が複数の資料に重複するときは、どれかを直したらほかも直す。スクリプトには「文面は原稿に合わせる」とコメントを置く

### 削れるものは削る

- 本編は、聞き手が判断するのに要る内容に絞る。実装の説明は付録に回し、付録の前に空のページを入れて区切る
- 1 枚のポスターには、全体が分かる最小限だけを残す
- 「決めること」には、聞き手に決めてほしいことだけを書く

### 画面録画を使うとき

- 個人の端末で撮った録画は、個人情報をぼかす。説明に関係するものは残す
- 音声がなければ外して圧縮する

## コミットの前に

- 日本語の文章は `lint-ja` で推敲する
